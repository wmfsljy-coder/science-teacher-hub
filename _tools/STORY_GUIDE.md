## 만들 것
맡은 단원 폴더에서 `index.html` 을 다시 쓰고 `episodes.js` 를 새로 만든다. 그 밖의 파일(assets, 다른 단원, 과목 첫 화면)은 건드리지 않는다. git 커밋·푸시도 하지 않는다. 브라우저 도구도 쓰지 않는다(검수자가 따로 돌려 본다).

## 구성 규칙
1. **이야기는 탭 하나 안에서 끝난다.** 기존 내용 탭(소단원) 하나 = 이야기 한 편 = `<div class="episode">` 하나. 페이지 전체를 한 이야기로 묶지 않는다. 기존 탭이 너무 크면 둘로 나눠도 되지만, 탭 수는 내용 탭 2~4개가 적당하다.
2. 이야기 한 편은 **장면 5개 안팎**: ① 사건·의뢰(말풍선 `.story`, 증거 `.case-file`) + 첫 추리(`sthGate`, 고르면 `ep.clear(0)`) → ②~④ 직접 조작하는 탐구와 미션 → ⑤ 결말(`.ending` 에 첫 추리와 결과를 나란히, 필요하면 `📎 과학자의 눈` 상자, `sthWork` 서술 2문항).
3. **호기심 → 조작 → 성취감.** 첫 장면은 진짜 궁금한 수수께끼·실제 사건으로 연다. 미션은 되도록 **시뮬레이션의 상태로 판정**한다(슬라이더를 움직여 값을 찾아내기, 조건을 만족하는 설계 찾기, 관찰 뒤 그래프 읽기). 자연스러운 곳에는 "너무 적어도, 너무 많아도 실패"하는 성공 구간을 둔다. 퀴즈(`sthPick`)·분류(`sthSort`)·순서(`sthOrder`)는 조작을 정리하는 용도로 쓴다. 이야기마다 **계산 모형이 들어간 조작 화면이 2개 이상** 있어야 한다. 단순 클릭-설명 카드로 때우지 않는다.
4. **내용은 기존보다 풍부하게.** 기존 시뮬레이션은 버리지 말고 이야기 속 장면으로 살리거나 개선한다. 해당 성취기준의 내용 요소가 빠짐없이 다뤄져야 한다.
5. 결말에서 `sthState("r1", "해결 · …핵심 결과…")` 처럼 이야기별 결과 문자열을 저장한다(r1, r2, …). 120자 이내.
6. 마지막 두 탭은 고정: **정리하기**(`sthWork` + `recap` 으로 r1… 표시, 이야기들을 꿰는 한 문장, 기존의 "아직 헷갈리는 것" 문항) , **우리 반**(`sthShare`, 시범 단원 그대로 단원 키·이름·rows 만 바꿔서).
7. 각 내용 탭 끝에 시범 단원과 같은 `teacher-note`(`?open=1`) 한 줄.

## 반드시 지킬 것 (호환)
- `window.sthUnit("…")` 의 단원 키는 기존 그대로. 기존 `sthWork` 문항 id(w1, w2, w3 …)는 **같은 id 로 재사용**한다(학생이 써 둔 답이 남아 있다). 기존 `sthGate` 의 key 도 가능하면 재사용.
- 성취기준 칩·원문(`std-chip`, `std-note`)은 글자 하나 바꾸지 말고, 해당 이야기 탭의 `stage-head` 로 나눠 싣는다. 모든 코드가 어딘가에 한 번은 나와야 한다.
- **오개념 지도 상자(`.miscon`)는 원문 그대로**(cite 포함) 관련 이야기의 결말이나 해당 장면에 넣는다. 가능하면 그 오개념이 이야기의 반전이 되게 짠다.
- `<title>`, `.rail .brand` 마크업, `<a class="home" href="../">` 는 유지.
- 스크립트 순서: theme.js → story.js → share-config.js → share.js → episodes.js. CSS: theme.css → story.css.

## 과학 정확성
- 실제 사례와 실제 수치를 쓴다. 확실하지 않은 수치·인용은 쓰지 않는다. 실존 과학자는 널리 확립된 사실만. 가상의 등장인물은 괜찮다.
- 단순화한 모형에는 결말에 `📎 과학자의 눈` 으로 한계를 밝힌다.
- 용어는 2022 개정 교과서 표기(이산화 탄소, 상호 작용, 산화·환원 …). 학생 말투는 고1~고2 수준, 존댓말 서술.

## 기술 규칙
- 시범 단원과 같은 ES5 문법(var, function), 외부 라이브러리 없음, 전체를 IIFE 로 감싼다.
- 캔버스는 `width="900"` 논리 좌표. **모든 글자·도형이 x 0~900, y 0~height 안에 들어오게** 한다(오른쪽 끝 라벨이 잘리기 쉽다). 색은 `cssVar("--token")` 만 쓴다. 그리기 함수는 `canvas._redraw = draw` 로 등록.
- 애니메이션은 `setTimeout` 으로(`requestAnimationFrame` 금지 — 가려진 탭에서 멈춘다).
- 진행·부분 성공은 `sthState` 로 저장하고, **다시 열었을 때 끝낸 장면의 미션 상자가 완료 상태로 보이게** 한다(시범 단원의 `if (ep.cleared(n)) sthMission(…)` 패턴).
- 슬라이더 미션은 `step` 으로 도달 가능한 값인지 반드시 확인한다.
- id 는 페이지 안에서 유일하게. 이야기 접두사를 붙인다(예: `a-`, `b-`, `c-`).

## 막히는 장면 만들지 않기 (중요)
- 미션 판정은 **되돌리기 버튼(‘처음부터’, ‘초기화’)을 누르지 않고도** 끝낼 수 있어야 한다. 되돌리기는 편의 기능일 뿐, 정답 경로의 필수 단계가 되면 안 된다.
- 슬라이더 두 개 이상이 **동시에** 특정 값이어야 통과하는 미션은 피한다. 하나씩 맞춰 가며 통과할 수 있게 짠다.
- 부분 성공은 즉시 저장한다(`sthState`). 한 조건을 맞춘 뒤 다른 조건을 맞추러 갔다가 앞 성공이 사라지면 안 된다.
- 애니메이션이 도는 동안 버튼을 잠갔다면 **반드시 다시 푼다**. 잠긴 채로 끝나면 학생이 갇힌다.
- 미션 상자에 `<li id="…">` 하위 항목을 두었으면 JS 의 `done("…")` 과 id 가 정확히 맞아야 한다.
